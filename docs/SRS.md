# เอกสารข้อกำหนดความต้องการของซอฟต์แวร์ (Software Requirements Specification : SRS)
## โครงการ: แพลตฟอร์มวัดระดับทักษะและสรุป Resume อิงสมรรถนะสำหรับนักศึกษา IT (Career-Path-Finding)

* **เวอร์ชันเอกสาร:** ฉบับสมบูรณ์ระยะนำร่อง (Release v1.0 MVP)
* **วันที่จัดทำ:** 13 พฤศจิกายน 2026
* **สถานะ:** รับรองความต้องการพร้อมเริ่มพัฒนา (Approved for Development)
* **ทีมวิเคราะห์ระบบ:** System Analyst (SA)

---

## 1. ภาพรวมระบบ (System Overview)

### 1.1 ระบบคืออะไร (What)
แพลตฟอร์มเว็บแอปพลิเคชันสำหรับ **ประเมินและวัดระดับสมรรถนะทักษะ (Skill Measurement)** ของนักศึกษาสาขาเทคโนโลยีสารสนเทศและบุคคลทั่วไป โดยอ้างอิงกรอบมาตรฐานสากล **SFIA (Skills Framework for the Information Age) เวอร์ชัน 9 (ระดับ 1–4)** ผ่านการวิเคราะห์ผลการเรียนในรายวิชา และหลักฐานกิจกรรม ผลงาน โครงงาน หรือใบรับรอง พร้อมทั้งมีระบบจับคู่สมรรถนะกับตำแหน่งงานเป้าหมาย (Job Match Analysis), แนะนำแผนที่เส้นทางการเรียนรู้ (Interactive Visual Flowchart Roadmap), สร้าง Resume อัจฉริยะที่สามารถส่งออกเป็นไฟล์ PDF หรือลิงก์สาธารณะ และเปิดพื้นที่ให้ผู้ประกอบการค้นหาบุคลากรที่มีทักษะตรงตามต้องการอย่างโปร่งใส

### 1.2 แก้ปัญหาอะไร (Why)
1. **ช่องว่างความรู้ของนักศึกษา (Skill Disconnect):** นักศึกษาไม่ทราบว่าวิชาที่เรียนหรือกิจกรรมที่ทำเชื่อมโยงกับทักษะที่ตลาดแรงงานต้องการอย่างไร ทำให้เลือกเรียนหรือทำกิจกรรมอย่างขาดเป้าหมาย
2. **เรซูเม่ขาดความน่าเชื่อถือ (Unverified Resume):** เรซูเม่ทั่วไปแสดงเพียงชื่อวิชาและเกรดเฉลี่ย ซึ่งไม่สามารถสะท้อนความสามารถในการทำงานจริง (Competency) และขาดหลักฐานยืนยัน
3. **ความยากลำบากในการสรรหาบุคลากร (Recruitment Friction):** ผู้ประกอบการต้องเสียเวลาและต้นทุนสูงในการคัดกรองผู้สมัคร เนื่องจากข้อมูลทักษะในใบสมัครไม่มีมาตรฐานวัดที่ชัดเจน
4. **การขาดข้อมูลเชิงประจักษ์ในการพัฒนาหลักสูตร (Curriculum Blind Spot):** ผู้บริหารสาขาวิชาขาดข้อมูลสถิติภาพรวมว่าหลักสูตรสร้างทักษะใดได้ดี และทักษะใดที่นักศึกษายังขาดแคลน

### 1.3 ใครได้ประโยชน์ (Stakeholders & Beneficiaries)
* **นักศึกษา (Students):** ทราบระดับทักษะที่แท้จริงของตนเอง เห็นช่องว่างทักษะ (Skill Gap) และมีแผนการเรียนรู้ที่ชัดเจนสู่ตำแหน่งงานในฝัน พร้อมได้ Resume ที่มีหลักฐานรับรอง
* **บุคคลภายนอก (External Learners):** สามารถใช้ระบบในการประเมินตนเองเทียบกับตำแหน่งงานด้าน IT และแสดงศักยภาพสู่สายตาผู้ประกอบการ
* **อาจารย์ผู้สอนและอาจารย์ที่ปรึกษา (Faculty Members):** มีเครื่องมือยืนยันความสามารถของนักศึกษาอย่างเป็นระบบ ลดภาระงานเอกสารด้วยการตรวจแบบกลุ่ม (Batch)
* **หัวหน้าสาขาวิชาและผู้บริหารหลักสูตร (Academic Administrators):** ได้รับรายงานสรุปช่องว่างทักษะของหลักสูตร (Curriculum Skill Gap) เพื่อใช้ปรับปรุง มคอ. และวางแผนการจัดการเรียนการสอน
* **ผู้ประกอบการ (Employers):** เข้าถึงฐานข้อมูลผู้มีความสามารถ (Talent Pool) ที่ผ่านการรับรองทักษะ สามารถค้นหาและคัดกรองตามทักษะที่ต้องการได้อย่างแม่นยำ

### 1.4 ขอบเขตของระบบ (System Scope)
* **ขอบเขตการนำร่อง:** รองรับหลักสูตรสาขาวิชาเทคโนโลยีสารสนเทศ (IT) ในสถาบันนำร่อง โดยมีชุดตำแหน่งงานตั้งต้น 5 ตำแหน่ง (Frontend Developer, Backend/Full-stack Developer, Data Analyst, Software QA/Tester, DevOps/Cloud Engineer) และรองรับการจัดการตำแหน่งงานแบบไดนามิก (Dynamic Role CRUD)
* **มาตรฐานทักษะ:** อิงรหัสทักษะและระดับความสามารถตามกรอบ SFIA 9 ในระดับ 1–4
* **สถาปัตยกรรม:** พัฒนาด้วย Laravel Full-stack Monolith (Blade + Tailwind CSS / Livewire) ร่วมกับฐานข้อมูล MySQL ออกแบบโครงสร้างให้สามารถ Deploy บน Host PHP ได้สะดวก พร้อมไฟล์ Docker Container สำหรับสภาพแวดล้อมการพัฒนาร่วมกัน

## 2. ผู้ใช้ระบบ (System Actors & Permissions)

| กลุ่มผู้ใช้ | คำอธิบาย | สิทธิ์และสิ่งที่ทำได้ในระบบ |
|---|---|---|
| **1. นักศึกษา (Student)** | นักศึกษาในมหาวิทยาลัยที่มีรายชื่อในระบบจากการนำเข้าข้อมูลของ Admin | • เข้าสู่ระบบด้วยรหัสนักศึกษา/อีเมลมหาวิทยาลัย และเปลี่ยนรหัสผ่าน<br>• จัดการโปรไฟล์ส่วนตัว และตั้งค่าความยินยอม PDPA<br>• ตั้งค่าความเป็นส่วนตัวแบบละเอียด (ซ่อน/แสดง เบอร์โทร, เกรด, ผลงาน)<br>• สำรวจตำแหน่งงาน ดูคะแนน % Job Match, กราฟ Radar, และ Skill Gap<br>• เปรียบเทียบ % Match พร้อมกันหลายตำแหน่ง (Multi-role Comparison)<br>• ดูแผนที่การเรียนรู้ 2 แทร็ก (วิชาในหลักสูตรตาม Prerequisite + กิจกรรมเสริม)<br>• ดูกราฟพัฒนาการการเติบโตของทักษะรายภาคเรียน (Skill Growth Snapshot)<br>• ยื่นหลักฐานผลงาน/กิจกรรม พร้อมเสนอระดับทักษะ SFIA (Self-declare)<br>• ดาวน์โหลด Resume PDF ภาษาไทย และสร้าง Shareable Web Link |
| **2. บุคคลภายนอก (External Learner)** | ผู้เรียนอิสระ ศิษย์เก่า หรือผู้สนใจทั่วไปที่เข้ามาใช้งานระบบ | • สมัครสมาชิกและเข้าสู่ระบบด้วยตนเองผ่านหน้าเว็บ<br>• ใช้งานระบบประเมินตนเอง ดู % Match, Radar Chart และ Roadmap ได้เหมือนนักศึกษา<br>• ยื่นหลักฐานผลงานและระบุทักษะแบบ Self-declared<br>• ดาวน์โหลด Resume PDF และสร้างลิงก์แชร์ออนไลน์ได้<br>• เปิดแสดงโปรไฟล์ให้ผู้ประกอบการค้นพบได้ โดยระบบจะติดป้ายกำกับชัดเจนว่าเป็น "บุคคลภายนอก (External / Self-declared)" |
| **3. อาจารย์ประจำวิชา (Course Instructor)** | อาจารย์ผู้รับผิดชอบรายวิชาในหลักสูตร | • เข้าใช้งานผ่านแท็บ *"วิชาที่ฉันสอน"* บนหน้า Dashboard รวมของอาจารย์<br>• ยืนยันผลการเรียนของนักศึกษาในรายวิชาที่รับผิดชอบแบบ Batch ผ่าน CSV<br>• ปรับแต่งเกณฑ์การแปลงเกรดเป็นระดับทักษะ SFIA ประจำวิชาของตนเองได้ |
| **4. อาจารย์ที่ปรึกษา (Advisor)** | อาจารย์ที่ปรึกษาทางวิชาการของกลุ่มนักศึกษา | • เข้าใช้งานผ่านแท็บ *"นักศึกษาในที่ปรึกษา"* บนหน้า Dashboard รวมของอาจารย์<br>• ตรวจสอบคิวงานหลักฐานกิจกรรม/โครงการ/ใบรับรองที่นักศึกษาในที่ปรึกษายื่นเข้ามา<br>• อนุมัติ (Approve พร้อมกำหนดระดับ) หรือ ปฏิเสธ (Reject พร้อมระบุเหตุผล)<br>• ดูภาพรวมจำนวนงานค้างตรวจบน Dashboard เพื่อติดตามความคืบหน้า |
| **5. หัวหน้าสาขาวิชา (Department Head)** | ผู้บริหารหลักสูตรและประธานสาขาวิชา | • มีสิทธิ์ตรวจอนุมัติหลักฐานทักษะระดับสูง (ระดับ 3 ขึ้นไป) หรือกรณีโต้แย้ง<br>• ตรวจสอบและอนุมัติการแก้ไขข้อมูลโครงสร้างหลักสูตรและ Role Profile<br>• เข้าถึง Dashboard ภาพรวมงานตรวจค้างของอาจารย์ทุกคนในสาขา<br>• ดูรายงานภาพรวมทักษะของหลักสูตร (Curriculum Skill Gap Report) |
| **6. ผู้ประกอบการ (Employer)** | ตัวแทนบริษัท ฝ่ายสรรหาบุคลากร (HR) หรือผู้ดูแลสหกิจศึกษา | • สมัครสมาชิกด้วยตนเองผ่านหน้าเว็บ และเข้าใช้งานได้ทันทีหลังยืนยันอีเมล<br>• ค้นหาและกรองรายชื่อผู้สมัครตามชุดทักษะ SFIA และระดับขั้นต่ำ<br>• ดูโปรไฟล์, Resume, และข้อมูลติดต่อ (อีเมล/เบอร์โทร/LinkedIn) ของนักศึกษาที่ Opt-in<br>• บันทึกรายชื่อนักศึกษาลงในรายการคัดเลือก (Shortlist)<br>• ส่งออกรายชื่อ Shortlist เป็นไฟล์ Excel/CSV<br>• กดปุ่ม "Express Interest" เพื่อส่งอีเมลแจ้งเตือนนักศึกษาอัตโนมัติว่าบริษัทสนใจ |
| **7. ผู้ดูแลระบบ (Admin)** | ทีมพัฒนาระบบหรือเจ้าหน้าที่ผู้ดูแลระบบเทคโนโลยีสารสนเทศ | • นำเข้าบัญชีนักศึกษาและอาจารย์แบบกลุ่ม (Batch Import CSV) พร้อมสร้างรหัสผ่านเริ่มต้น<br>• จัดการข้อมูลหลัก (Master Data): Skill Catalog, Job Role CRUD, และ Course Mapping<br>• นำเข้าข้อมูลรายวิชาและเกรดของนักศึกษา พร้อมหน้าจอตรวจสอบล่วงหน้า (Preview/Pre-validation)<br>• ดูแลรายงานสถิติการใช้งาน, จัดการความยินยอม PDPA, และดูบันทึก Audit Log<br>• ส่งออกชุดข้อมูลนิรนาม (Anonymized Data CSV) สำหรับงานวิจัย |

## 3. ฟีเจอร์ "ต้องมี" (Must-Have Features — MVP)

| รหัส | ชื่อฟีเจอร์ | ผู้ใช้ที่เกี่ยวข้อง | รายละเอียดการทำงาน | เกณฑ์ว่าทำเสร็จแล้ว (Acceptance Criteria) | ระยะเวลาพัฒนา (วัน) |
|---|---|---|---|---|:---:|
| **F01** | ระบบจัดการบัญชีและยืนยันตัวตน (Local Auth & Provisioning) | ทุกกลุ่มผู้ใช้ | • Admin นำเข้าบัญชีนักศึกษา/อาจารย์จาก CSV พร้อมรหัสผ่านเริ่มต้น<br>• บุคคลภายนอกและผู้ประกอบการสมัครสมาชิกได้เองทางหน้าเว็บ<br>• ระบบตรวจสอบความถูกต้องของอีเมล (Email Verification)<br>• บังคับ/อนุญาตให้เปลี่ยนรหัสผ่านและรีเซ็ตรหัสผ่านได้ | • นำเข้า CSV 500 บัญชีได้ภายใน 1 นาที<br>• บัญชีที่นำเข้าสามารถล็อกอินและเปลี่ยนรหัสผ่านได้สำเร็จ<br>• ผู้ใช้ใหม่สมัครสมาชิกและยืนยันอีเมลเข้าใช้งานได้ถูกต้อง | 4 |
| **F02** | การจัดการสิทธิ์และมุมมองอาจารย์ (Unified Faculty Dashboard) | อาจารย์ (ผู้สอน/ที่ปรึกษา), หน.สาขา | • ออกแบบระบบ RBAC รวมใน 1 บัญชีผู้ใช้<br>• Dashboard อาจารย์แบ่งเป็น 2 แท็บ: *"วิชาที่ฉันสอน"* (ยืนยันเกรด) และ *"นักศึกษาในที่ปรึกษา"* (ตรวจกิจกรรม)<br>• แสดงตัวเลข Badge งานค้างตรวจในแต่ละแท็บ | • อาจารย์ที่มีหลายบทบาทล็อกอินครั้งเดียวแล้วเห็นงานทั้งสองส่วนแยกแท็บชัดเจน<br>• จำนวนงานค้างตรวจแสดงผลตรงกับฐานข้อมูลจริง | 3 |

## 6. ข้อกำหนดความต้องการผู้ใช้ (User Stories)

### ฝั่งนักศึกษาและบุคคลภายนอก (Students & External Learners)
* **US01:** ในฐานะ **นักศึกษา** ฉันต้องการ **สำรวจตำแหน่งงานเป้าหมายและดูคะแนน % Job Match พร้อมกราฟ Radar Chart** เพื่อ **ประเมินว่าตนเองมีทักษะสอดคล้องกับอาชีพที่อยากทำมากน้อยเพียงใด**
* **US02:** ในฐานะ **นักศึกษา** ฉันต้องการ **เห็นธงแจ้งเตือนชัดเจนเมื่อตนเองขาดทักษะจำเป็น (Must-have)** เพื่อ **ให้ความสำคัญกับการปิดช่องว่างทักษะวิกฤตเหล่านั้นก่อน**
* **US03:** ในฐานะ **นักศึกษา** ฉันต้องการ **ดูแผนผังการเรียนรู้ (Visual Roadmap Flowchart) ที่แยกแทร็กวิชาเรียนตามเงื่อนไข Prerequisite และแทร็กกิจกรรมเสริม** เพื่อ **วางแผนลงทะเบียนเรียนในแต่ละเทอมได้อย่างถูกต้อง**
* **US04:** ในฐานะ **นักศึกษา** ฉันต้องการ **ยื่นหลักฐานโครงงาน/ใบรับรอง พร้อมระบุทักษะ SFIA ที่คาดว่าจะได้รับ (Self-declare)** เพื่อ **ให้อาจารย์ที่ปรึกษาตรวจประเมินและรับรองระดับทักษะ**
* **US05:** ในฐานะ **นักศึกษา** ฉันต้องการ **สร้างและดาวน์โหลด Resume ภาษาไทยเป็นไฟล์ PDF ได้ในเวลาอันสั้น** เพื่อ **นำไปใช้ยื่นสมัครงานหรือฝึกงานได้ทันที**
* **US06:** ในฐานะ **นักศึกษา** ฉันต้องการ **สร้างลิงก์แชร์ Resume ออนไลน์ที่กำหนดวันหมดอายุได้และดูกราฟสถิติจำนวนคนเข้าชม** เพื่อ **นำไปแนบใน Portfolio ออนไลน์ได้อย่างปลอดภัย**
* **US07:** ในฐานะ **นักศึกษา** ฉันต้องการ **ตั้งค่าความเป็นส่วนตัวแบบละเอียด เช่น ซ่อนเบอร์โทรหรือเกรดดิบ** เพื่อ **คุ้มครองข้อมูลส่วนตัวและเปิดเผยเฉพาะระดับทักษะที่ผ่านการรับรอง**
* **US08:** ในฐานะ **บุคคลภายนอก** ฉันต้องการ **สมัครสมาชิกเข้าใช้งานระบบได้ด้วยตนเอง** เพื่อ **ประเมินความพร้อมด้านทักษะ IT ของตนเองและสร้าง Resume อิงสมรรถนะ**

### ฝั่งอาจารย์และผู้บริหาร (Faculty & Department Head)
* **US09:** ในฐานะ **อาจารย์ประจำวิชา** ฉันต้องการ **ยืนยันผลการเรียนของนักศึกษาทั้งห้องเรียนผ่านไฟล์ CSV ในหน้าแท็บ "วิชาที่ฉันสอน"** เพื่อ **ลดภาระงานเอกสารและยืนยันคะแนนได้อย่างรวดเร็ว**
* **US10:** ในฐานะ **อาจารย์ประจำวิชา** ฉันต้องการ **ปรับแต่งเกณฑ์การแปลงเกรดเป็นระดับทักษะเฉพาะวิชาของตนเองได้** เพื่อ **สะท้อนความยากง่ายและผลลัพธ์การเรียนรู้ (CLO) ของวิชาได้อย่างเที่ยงตรง**
* **US11:** ในฐานะ **อาจารย์ที่ปรึกษา** ฉันต้องการ **ตรวจหลักฐานกิจกรรมและโครงงานของนักศึกษาในที่ปรึกษาผ่านหน้าแท็บ "นักศึกษาในที่ปรึกษา"** เพื่อ **ตรวจสอบผลงานจริงและอนุมัติระดับทักษะให้แก่นักศึกษา**
* **US12:** ในฐานะ **อาจารย์และหัวหน้าสาขา** ฉันต้องการ **เห็นตัวเลขสรุปงานค้างตรวจบนหน้าจอ Dashboard** เพื่อ **ติดตามความคืบหน้าการตรวจงานได้อย่างต่อเนื่อง**
* **US13:** ในฐานะ **หัวหน้าสาขาวิชา** ฉันต้องการ **ดูรายงานภาพรวมช่องว่างทักษะของหลักสูตร (Curriculum Skill Gap)** เพื่อ **นำข้อมูลไปใช้ปรับปรุงแผนการสอนและหลักสูตร มคอ. ให้ตรงกับความต้องการของตลาด**

### ฝั่งผู้ประกอบการ (Employers)
* **US14:** ในฐานะ **ผู้ประกอบการ** ฉันต้องการ **สมัครสมาชิกและเริ่มค้นหาผู้สมัครได้ทันทีหลังยืนยันอีเมล** เพื่อ **สรรหาผู้มีความสามารถได้รวดเร็วโดยไม่ต้องรอการอนุมัติบัญชี**
* **US15:** ในฐานะ **ผู้ประกอบการ** ฉันต้องการ **ค้นหาและกรองนักศึกษาตามระดับทักษะ SFIA ขั้นต่ำที่ต้องการ** เพื่อ **พบผู้สมัครที่ทำงานได้จริงอย่างตรงเป้าหมาย**
* **US16:** ในฐานะ **ผู้ประกอบการ** ฉันต้องการ **เห็นป้ายกำกับชัดเจนระหว่างนักศึกษาในสถาบัน (Verified) กับบุคคลภายนอก (Self-declared)** เพื่อ **ใช้เป็นข้อมูลประกอบการตัดสินใจคัดเลือกได้อย่างถูกต้อง**
* **US17:** ในฐานะ **ผู้ประกอบการ** ฉันต้องการ **บันทึกนักศึกษาที่ผ่านเกณฑ์ลงใน Shortlist และส่งออกเป็นไฟล์ CSV/Excel** เพื่อ **นำรายชื่อไปดำเนินกระบวนการสรรหาภายในบริษัทต่อไป**
* **US18:** ในฐานะ **ผู้ประกอบการ** ฉันต้องการ **กดปุ่ม Express Interest เพื่อส่งอีเมลแจ้งความสนใจไปยังนักศึกษา** เพื่อ **เปิดโอกาสให้นักศึกษาติดต่อกลับเพื่อนัดหมายสัมภาษณ์**

### ฝั่งผู้ดูแลระบบ (Administrators)
* **US19:** ในฐานะ **Admin** ฉันต้องการ **นำเข้าบัญชีนักศึกษา/อาจารย์จากไฟล์ CSV พร้อมสร้างรหัสผ่านเริ่มต้น** เพื่อ **ตั้งค่าผู้ใช้งานระบบนำร่องได้อย่างสะดวกรวดเร็ว**
* **US20:** ในฐานะ **Admin** ฉันต้องการ **ตรวจสอบตัวอย่างข้อมูล (Preview) และจุดผิดพลาดก่อนบันทึกไฟล์ CSV รายวิชาและเกรด** เพื่อ **ป้องกันความผิดพลาดและข้อมูลตกหล่นในฐานข้อมูล**
* **US21:** ในฐานะ **Admin** ฉันต้องการ **ส่งออกชุดข้อมูลนิรนาม (Anonymized Data CSV) ที่ตัดข้อมูลระบุตัวตนออก** เพื่อ **นำไปให้นักวิจัยวิเคราะห์ค่าสถิติและความเที่ยงตรงของระบบ**

## 7. ข้อกำหนดที่ไม่ใช่เชิงหน้าที่และข้อจำกัดทางเทคนิค (NFR & Constraints)

### 7.1 ประสิทธิภาพและความเร็ว (Performance)
* **NFR-PERF-01:** หน้าจอเว็บแอปพลิเคชันหลักต้องโหลดเสร็จสิ้นภายใน **3 วินาที** ภายใต้การใช้งานพร้อมกัน (Concurrent Users) อย่างน้อย 100 คน
* **NFR-PERF-02:** อัลกอริทึมการคำนวณระดับทักษะและคะแนน % Job Match ต่อนักศึกษา 1 คน ต้องประมวลผลเสร็จสิ้นภายใน **2 วินาที**
* **NFR-PERF-03:** การสร้างและดาวน์โหลดไฟล์ **Resume PDF ภาษาไทย ต้องเสร็จสิ้นภายใน 10 วินาที**
* **NFR-PERF-04:** การนำเข้าและตรวจสอบไฟล์ Batch CSV ขนาด 500 แถว ต้องประมวลผลเสร็จสิ้นภายใน **1 นาที**

### 7.2 ความมั่นคงปลอดภัยและการคุ้มครองข้อมูล (Security & PDPA)
* **NFR-SEC-01:** ข้อมูลการสื่อสารทั้งหมดต้องทำงานผ่านโพรโทคอล **HTTPS (TLS 1.3)**
* **NFR-SEC-02:** รหัสผ่านต้องถูกเข้ารหัสด้วยอัลกอริทึมมาตรฐาน **Bcrypt** หรือ **Argon2id** พร้อม Salt
* **NFR-SEC-03:** การควบคุมสิทธิ์ต้องตรวจสอบที่ฝั่งเซิร์ฟเวอร์ (Server-side RBAC Enforcement) ทุก Request ผ่าน Laravel Middleware
* **NFR-SEC-04:** ป้องกันช่องโหว่พื้นฐานตามมาตรฐาน **OWASP Top 10** (SQL Injection, XSS, CSRF, Mass Assignment)
* **NFR-SEC-05:** ไฟล์หลักฐานที่อัปโหลดต้องถูกจัดเก็บนอก Web Root พร้อมตรวจสอบ MIME-Type จริง และเข้าถึงผ่านสิทธิ์ในระบบเท่านั้น
* **NFR-SEC-06:** ปฏิบัติตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA) อย่างเคร่งครัด โดยผู้ใช้สามารถจัดการความยินยอม และเลือกขอลบบัญชีถาวรตามสิทธิที่จะถูกลืม (Right to be Forgotten)
* **NFR-SEC-07:** ห้ามใช้ข้อมูลอ่อนไหว (เพศ, ศาสนา, เชื้อชาติ) ในการจัดอันดับหรือกรองผลการค้นหาโดยเด็ดขาด

### 7.3 ความพร้อมใช้งานและการสำรองข้อมูล (Availability & Backup)
* **NFR-AVL-01:** ระบบต้องมีความพร้อมใช้งาน (Uptime) ไม่น้อยกว่า **95%** ในช่วงการนำร่องทดสอบ
* **NFR-AVL-02:** มีระบบสำรองฐานข้อมูล (Database Backup) อัตโนมัติทุกวัน และจัดเก็บย้อนหลังอย่างน้อย **7 วัน**

### 7.4 การออกแบบและการใช้งานบนอุปกรณ์ (Usability & Responsiveness)
* **NFR-USA-01:** ส่วนประสานงานผู้ใช้รองรับ **Responsive Web Design เต็มรูปแบบ**:
  * ฝั่งนักศึกษาและบุคคลภายนอก: ออกแบบและทดสอบให้ใช้งานบนสมาร์ทโฟน (Mobile Responsive) ได้อย่างสะดวก 100%
  * ฝั่งอาจารย์, หัวหน้าสาขา, ผู้ประกอบการ และ Admin: เน้นการแสดงผลที่สมบูรณ์แบบบนคอมพิวเตอร์และแท็บเล็ต (Desktop/Tablet)
* **NFR-USA-02:** รองรับเว็บเบราว์เซอร์มาตรฐานรุ่นล่าสุด ได้แก่ Google Chrome, Microsoft Edge, Safari และ Mozilla Firefox
* **NFR-USA-03:** การแสดงผลภาษาไทยในไฟล์ PDF ต้องตัดคำถูกต้อง และจัดวางสระ/วรรณยุกต์ได้อย่างสมบูรณ์ ไม่ลอยหรือไม่ทับซ้อน

### 7.5 สถาปัตยกรรมและโครงสร้างพื้นฐาน (Architecture & Hosting)
* **Backend & Frontend:** พัฒนาด้วย **Laravel Full-stack Monolith (PHP 8.2+)** ร่วมกับ Blade Templates, Tailwind CSS และ Alpine.js / Livewire
* **Database:** **MySQL 8.0+** หรือ MariaDB 10.5+
* **Deployment Constraints:** ออกแบบโครงสร้างระบบให้สามารถ **ติดตั้งและ Deploy บน Host PHP ทั่วไปได้ง่ายดายเป็นหลัก** และจัดเตรียม **Docker Container (`Dockerfile`, `docker-compose.yml`)** สำหรับการพัฒนาและทดสอบร่วมกันในทีม รวมถึงรองรับการย้ายขึ้น Cloud หรือ VM ในอนาคต
* **Budget Constraint:** พัฒนาภายใต้กรอบงบประมาณ **20,000–35,000 บาท** โดยใช้ซอฟต์แวร์ Open Source และทรัพยากรฟรีของสถาบันเป็นหลัก
